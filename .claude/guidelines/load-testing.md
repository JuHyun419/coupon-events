# 부하 테스트 가이드라인

## 목적

- 실제 트래픽 패턴에서의 성능 병목 파악
- SLA(응답시간, 에러율) 기준 충족 여부 검증
- 배포 전 용량 계획 검토

---

## 테스트 유형

| 유형 | 목적 | 기준 |
|------|------|------|
| Smoke Test | 기본 동작 확인 | 최소 부하 (VU 1~5) |
| Load Test | 예상 트래픽 처리 능력 | 평균 트래픽 기준 |
| Stress Test | 한계점 탐색 | 부하를 점진적으로 증가 |
| Soak Test | 장시간 안정성 | 일정 부하를 장시간 유지 |

---

## 주요 지표

- **Throughput**: 초당 처리 건수 (RPS/TPS)
- **Latency**: p50, p95, p99 응답시간
- **Error Rate**: 5xx 비율 (목표: < 0.1%)
- **Resource**: CPU, Memory, DB Connection Pool 사용률

---

## 이 프로젝트의 주요 시나리오

- **배치 발행 스케줄러**: 점심/저녁 특정 시간에 대량 Kafka 메시지 발행 — 피크 시 Kafka 처리량 및 Consumer Lag 모니터링
- **Redis 캐시 조회**: `getCandidatePostIds` 호출 시 Redis 응답 지연 및 캐시 미스율
- **Consumer 처리**: 배치 메시지 수신 후 실제 푸시 발송 처리 속도

---

## 주의사항

- 부하 테스트는 운영 환경이 아닌 스테이징 환경에서 실행한다.
- 테스트 후 생성된 더미 데이터는 반드시 정리한다.
- Kafka, Redis, DB 각각의 한계를 개별로 파악한 후 통합 테스트를 진행한다.
